   .. rubric:: 模块职责

   这个 module wrapper 汇入三维柱坐标 ``r-phi-z`` Yee 网格的 CPML 电场和磁场更新核。
   它负责把 ``sub_E02_cpml_3d_cylindrical_E`` 与 ``sub_E02_cpml_3d_cylindrical_H`` 暴露在同一个
   Fortran module 中；实际的场更新、CPML memory variables 和轴线闭合都在两个子例程页面中说明。

   .. rubric:: 公开入口 / include 关系

   .. list-table::
      :header-rows: 1
      :widths: 30 34 36

      * - 入口 / 文件
        - 角色
        - 关系
      * - ``sub_E02_cpml_3d_cylindrical_E``
        - 在柱坐标 CPML 区域中更新 ``Er/Ephi/Ez``，并推进电场更新所需的六个 ``psi_E_*`` memory variables。
        - 由本 module 的 ``contains`` 段通过 ``#include`` 汇入。
      * - ``sub_E02_cpml_3d_cylindrical_H``
        - 在柱坐标 CPML 区域中更新 ``Hr/Hphi/Hz``，并推进磁场更新所需的六个 ``psi_H_*`` memory variables。
        - 由本 module 的 ``contains`` 段通过 ``#include`` 汇入。

   .. rubric:: 局部假设

   - 模块面向完整三维柱坐标 ``r-phi-z`` 六分量场，保留 ``phi`` 方向差分项。
   - CPML 系数数组由上层按照吸收层剖面预先生成；本 module 不生成 ``a/b/k`` 系数。
   - ``psi_*`` memory variables 必须跨时间步保存，只应在重新初始化吸收层时清零。
   - 模块本身不分配场数组、不保存全局网格参数、不执行 MPI exchange，也不注入源项。
   - 物理轴线 ``i=0`` 的闭合由子例程处理；MPI 子域的局部下标 0 不能自动等同于物理轴线。

   .. rubric:: 实现逻辑

   - 源码中的 ``contains`` 段只通过 Fortran 预处理器汇入两个 ``sub_*.f90`` 文件。
   - 电场和磁场 CPML 核都在普通柱坐标 curl 差分外增加
     ``psi = b*psi + a*d`` 的 memory update，并用对应方向的 ``k`` 系数缩放差分项。
   - 柱坐标中的 ``1/r`` 和 ``d(rF)/dr`` metric 项保留在具体子例程中处理，避免 module 层隐藏几何约定。

   .. rubric:: 调用注意

   - 上层代码应 ``use mod_E02_cpml_3d_cylindrical``，然后按 Yee leapfrog 时间层直接调用 ``H`` 和 ``E`` 更新入口。
   - 编译时需要启用预处理，并让编译器能找到被 ``#include`` 的两个子例程源文件。
   - 若只在吸收层调用 CPML 子例程，内部普通区域可继续使用 ``mod_E02_fdtd_3d_cylindrical`` 中的非 CPML 更新。

   .. rubric:: Module Role

   This module wrapper collects the CPML electric- and magnetic-field update
   kernels for the 3D cylindrical ``r-phi-z`` Yee grid. It exposes
   ``sub_E02_cpml_3d_cylindrical_E`` and ``sub_E02_cpml_3d_cylindrical_H`` from a single
   Fortran module; the actual field updates, CPML memory variables, and axis
   closures are documented on the two subroutine pages.

   .. rubric:: Public Entries / Include Relation

   .. list-table::
      :header-rows: 1
      :widths: 30 34 36

      * - Entry / File
        - Role
        - Relation
      * - ``sub_E02_cpml_3d_cylindrical_E``
        - Updates ``Er/Ephi/Ez`` in the cylindrical CPML region and advances the six ``psi_E_*`` memory variables used by the electric update.
        - Included into this module's ``contains`` section through ``#include``.
      * - ``sub_E02_cpml_3d_cylindrical_H``
        - Updates ``Hr/Hphi/Hz`` in the cylindrical CPML region and advances the six ``psi_H_*`` memory variables used by the magnetic update.
        - Included into this module's ``contains`` section through ``#include``.

   .. rubric:: Local Assumptions

   - The module targets full 3D cylindrical ``r-phi-z`` six-component fields and keeps the ``phi``-direction derivative terms.
   - CPML coefficient arrays are generated by the caller from the absorbing-layer profile; this module does not build ``a/b/k`` coefficients.
   - ``psi_*`` memory variables must persist across time steps and should only be cleared when the absorbing layer is reinitialized.
   - The module itself does not allocate fields, store global mesh parameters, perform MPI exchange, or inject sources.
   - The physical axis closure at ``i=0`` is handled by the subroutines; an MPI-local index 0 must not be treated as the physical axis automatically.

   .. rubric:: Implementation Notes

   - The source ``contains`` section only includes the two ``sub_*.f90`` files through the Fortran preprocessor.
   - Both CPML kernels add ``psi = b*psi + a*d`` memory updates to the standard cylindrical curl differences and scale directional derivatives by the corresponding ``k`` coefficients.
   - Cylindrical metric terms such as ``1/r`` and ``d(rF)/dr`` stay in the concrete subroutines so the geometry convention remains explicit.

   .. rubric:: Calling Notes

   - Caller code should ``use mod_E02_cpml_3d_cylindrical`` and call the ``H`` and ``E`` update entries directly in Yee leapfrog order.
   - Compilation must enable preprocessing and make the two included subroutine source files visible to the compiler.
   - If CPML routines are called only in absorbing layers, interior regular regions can continue to use the non-CPML updates from ``mod_E02_fdtd_3d_cylindrical``.
