# AlgoPlasma collaboration guidance

## Explanatory documentation

When creating or substantially revising explanations, derivations, examples,
figures, animations, or interactive demonstrations, first read:

- [Documentation structure and language conventions](docs/DOCUMENTATION_GUIDE.md)
- [Evidence-informed teaching design](docs/TEACHING_GUIDE.md)
- [Development workflow](docs/CODEX_DEVELOPMENT_GUIDE.md)

Apply the teaching guide as a default, scaled to the page and audience. Establish
the prerequisite chain and intended reader capability; connect diagrams, formulas
and code; keep essential assumptions visible; use optional details and meaningful
interactions when they help. Do not impose quizzes or animations on every page.

Explicit user instructions take precedence. This guidance does not authorize
changes outside the requested module, solver behavior changes, or an automatic
rewrite of existing pages. Preserve user edits and public interfaces. State what
was checked; do not claim that a documentation build proves learning effectiveness.

## Plasma-wave learning module

When creating or revising the plasma-wave lessons in
`docs/source/_static/plasma_waves/` or `docs/source/learning/plasma_waves/`,
also read the [module authoring rules](docs/source/learning/plasma_waves/AUTHORING_RULES.md).
These user-confirmed rules guide lesson content, layout, animation, navigation
and bilingual updates. Keep author-facing instructions in the author documentation.
